# Line format (indentation = depth; a child sits one level below its parent):
#   <id>[ ?]  | <content, the report's words, short>  | <edge / provenance note>
# A bare id at claim depth (deepest level) is an ATOMIC-CLAIM LEAF; its text, route and source live in
# claims-machine.txt and are not repeated here. Node ids are single tokens (the parser reads fields[0]
# before the first "|"), so a finding's full phrasing leads its content column.
#
# Edge markers (spec/ARGUMENT.md § Edges):
#   (default)  load-bearing, subject-for-subject: the recommendation directly acts on / remedies the
#              finding, or the finding decomposes to the claim.
#   ?          the report does NOT establish this edge — it presents the recommendation but never rests
#              it on one named finding (its basis is the whole amplifier thesis). A question for a
#              human, not a guess; candidate findings are named in the note.
#   [opinion]  a route=evaluative leaf — never judged; contributes nothing to a parent's hold/fail.
#
# ATTACHMENT — read this. This report's spine is unusually clean: its "practical advice" (p63–64) is a
# list of imperatives, and each imperative names exactly the DORA AI Capability whose moderation finding
# licenses it. So the SEVEN capabilities are the recommendation tier, each attached subject-for-subject
# to its one capability finding (F-STANCE … F-PLAT), and each finding's leaf is the single atomic claim
# that states that moderation result (CM4 … CM10) plus any cross-chapter RESTATEMENT of the same finding
# — the pair being an internal-consistency check, since report.pdf is the only held source and the
# figures must agree across chapters (ES/FT/PE restatements below). Two cross-cutting recommendations
# have no single-capability basis: VSM (R-VSM, its own chapter's moderation finding) attaches to F-VSM,
# and "treat AI adoption as an organizational transformation" (R-TRANSFORM) is childless-? because the
# report rests it on the whole systems thesis, not one finding — candidates F-SYSTEM and F-IMPACT are
# named and attached elsewhere.
#
# Two foundational findings that NO recommendation remedies hang under `base`: F-IMPACT (the landscape
# of AI's estimated effects, Figure 28 — the empirical core the amplifier thesis rests on) and
# F-SYSTEM (the AI-mirror claim that AI's effect depends on the surrounding system).
#
# NOT in this tree, by design: the report's apparatus and context are checkable claims in

# third-party figures (EX2–EX9), the sociocognitive results (EX16–EX22), the metrics-frameworks asides

# CM12 (the advice imperatives themselves) are attached as opinion/apparatus where they name a rec.
#
